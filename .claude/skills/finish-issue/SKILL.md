# 이슈 작업 마무리

## 순서

1. **검증 확인**: 마지막 코드 변경 이후에 `/verify` 가 통과했는지 확인한다. 아니면 먼저 돌린다.
2. **검토**: `reviewer` 서브에이전트에게 변경분 검토를 맡기고, 지적 사항을 반영하거나 반영하지 않는 이유를 정리한다.
3. **PROMPTS.md 정리**: 이번 이슈의 프롬프트를 한 항목으로 묶는다.
   - 형식: `## <번호>. <제목> (#이슈)` → 프롬프트 원문(인용문) → **구현 요소** → **결과**
   - 프롬프트 원문은 고치지 않는다. 시스템이 끼워 넣은 내용이 섞였으면 그것만 지운다.
   - 어떤 프롬프트를 남길지 사용자에게 확인받는다.
4. **변경 내용 보여주기**: `git status -sb` 와 변경 요약, 커밋 메시지, PR 제목을 보여주고 **확인을 받는다.** 확인 전에는 커밋하지 않는다.
5. **커밋**: 파일을 지정해서 올린다. (`git add -A` 로 전부 올리지 않는다.)
   - 제목: `<type>(<scope>): <요약> (#<이슈>)`. type 은 `feat`, `fix`, `docs`, `chore`, `test`, `refactor`
   - 본문: 무엇을 왜 바꿨는지 두세 문장
   - 결정 맥락이 있으면 트레일러로 남긴다: `Constraint:`, `Rejected:`, `Directive:`, `Confidence:`, `Scope-risk:`, `Not-tested:`
6. **푸시**: `git push -u origin <브랜치>`. 인증에서 거부되면 `gh auth status` 로 계정을 확인하고 `gh auth setup-git` 후 다시 시도한다.
7. **PR 생성**: `gh pr create --base main`
   - 제목: 이슈 제목과 같게 (`[Search] 최근 검색어`)
   - 라벨: 이슈와 같게
   - 본문: 첫 줄 `Closes #<이슈>`, 이어서 `## 변경 내용`, `## 검증`, `## 확인하지 않은 것`
8. **보고**: PR 링크, 커밋, 확인하지 못한 것을 알린다. **머지는 하지 않는다.**

## 주의

- 이슈의 작업 체크리스트와 결정 사항이 실제 구현과 다르면 이슈 본문을 맞춘다.
- 실패한 테스트나 건너뛴 단계가 있으면 그대로 적는다.
