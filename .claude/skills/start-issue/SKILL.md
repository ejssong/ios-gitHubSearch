# 이슈 작업 시작

대상 이슈: `$ARGUMENTS` (번호가 없으면 어느 이슈인지 먼저 묻는다.)

## 순서

1. **이슈 읽기**: `gh issue view <번호> --json number,title,body,labels,state` 로 목표, 작업, 결정 사항, 완료 조건을 읽는다. 닫힌 이슈면 멈추고 알린다.
2. **작업 트리 확인**: `git status -sb` 가 깨끗한지 본다. 커밋되지 않은 변경이 있으면 멈추고 어떻게 할지 묻는다.
3. **main 최신화**: `git switch main` 후 `git pull --ff-only origin main`.
4. **브랜치 만들기**: `<종류>/<번호>-<짧은-영문-설명>`. 종류는 이슈 라벨이 `fix` 면 `fix`, 아니면 `feature`. 예: `feature/3-recent-searches`
5. **계획 보여주기**: 코드를 쓰기 전에 아래를 정리해서 보여준다.
   - 바꾸거나 만들 파일과 그 폴더 (`CLAUDE.md` 의 폴더 역할을 따른다)
   - 상태·액션·의존성의 초안
   - 추가할 테스트
   - 이슈의 결정 사항만으로 정해지지 않는 부분은 질문으로, 각 질문에 추천안을 붙인다
6. **승인 대기**: 사용자가 계획을 확인하기 전에는 구현을 시작하지 않는다.

## 주의

- 이슈의 결정 사항과 다르게 구현해야 하면 먼저 알리고, 합의되면 이슈 본문부터 고친다.
- 이슈 범위 밖의 변경은 하지 않는다. 필요해 보이면 새 이슈를 제안한다.
